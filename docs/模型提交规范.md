# 模型提交规范

本文说明研讨课学生如何交付可被当前平台加载的模型。统一的是选手调用协议，学生自行提供编码器、网络结构、合法性处理、解码器和权重。训练与加载示例见[PyTorch模型训练与接入示例](PyTorch模型训练与接入示例.md)。

## 1 提交内容与目录

推荐每个选手一个顶层入口，其余文件放独立子目录：

```text
agents/
  team_alpha.py              # 平台扫描入口
  team_alpha/
    __init__.py
    model.py                 # 网络定义
    codec.py                 # 学生编码与解码
    rules.py                 # 可选：学生自己的合法性实现
    weights.pt
    requirements.txt
    README.md
    LICENSE                  # 适用时提供
```

`team_alpha.py`的内部模块可通过`agents.team_alpha.model`等绝对导入。入口使用`Path(__file__).resolve()`定位随附文件；不要依赖个人电脑绝对路径，也不要假定模块导入时的工作目录等于权重目录。

最少需要：

| 材料 | 要求 |
|---|---|
| 选手入口 | 一个可无参数实例化的`Agent`或`TorchAgent`子类，提供清晰name |
| 模型定义 | 可重建网络，说明结构与checkpoint匹配关系 |
| 编码器 | 说明输入字段、形状、dtype、视角、通道和归一化 |
| 解码器 | 将网络输出转为小写UCI，处理升变与非法输出 |
| 合法性方案 | 自行实现或学生自行调用规则库，不依赖平台动作列表 |
| 权重文件 | 说明格式、文件名、哈希及加载方法 |
| 环境说明 | Python/PyTorch版本、额外依赖、CPU/GPU要求 |
| 运行说明 | 一条自测命令、一条对战命令及已验证结果 |
| 来源说明 | 训练数据、预训练模型、外部代码的来源和适用许可 |

一个裸`.pt/.pth`文件无法告诉平台网络架构和输入输出语义，不构成完整提交。可以提交state_dict、学生自定义checkpoint或其他可加载形式，但必须提供相应代码。

## 2 平台发现机制

当前扫描仅遍历`agents/`**第一层**`*.py`，跳过以下划线开头的文件；不会递归扫描学生子目录。一个文件可以包含辅助类，但应仅导出一个用于参赛的具体选手类；当前加载器会取模块中最后一个候选Agent子类，不能依赖多个类同时注册。

扫描会导入模块、实例化选手并关闭实例。不得在导入或无参数构造阶段开始训练、开窗口、连接平台、运行无限循环或加载大模型。构造器若重写应调用`super().__init__()`；加载权重放在`load_model()`或`on_game_start()`。

PyTorch是可选依赖。推荐只在模型初始化等真正需要时导入torch，避免缺少PyTorch时影响基础平台选手列表。`TorchAgent`已支持这种延迟初始化。

比赛spec示例为`agents/team_alpha.py`，不要提交Python类名代替文件路径。入口出现在下拉框只说明可导入和实例化，不保证权重或推理已成功；必须实际开局验收。

## 3 输入输出约定

输入为完整只读State：棋子矩阵、走子方、FEN、易位权、EP目标、计数、历史与裁判状态。矩阵固定第0行第8横线，`a8`在左上；颜色字段为`w/b`。若模型使用旋转、镜像或当前走子方视角，编码器与解码器必须互相对应。

平台不提供`State.legal_moves`、`Board.moves_from()`、动作掩码、`State.apply()`或`/legal_moves`。自行使用python-chess等库属于学生实现；不得访问平台私有字段、修改裁判或依赖管理接口规避规则。

最终输出有两种形式：

1. `choose_move(state)`返回UCI，例如`"g1f3"`，由平台提交；
2. 学生解码后执行`return self.game.submit(move)`，返回Result。

采用`TorchAgent`时，实现`load_model/encode/decode`即可，继承的`choose_move()`会主动提交。多输入网络可以覆盖`predict()`。不要求A/B网络具有相同输入输出形状。

None会被自动驱动器视为弃权；不能用来表示无输出、等待、跳过回合。学生应自行处理不稳定输出与合法性，平台不会自动把非法动作改成另一手棋。

完整字段及错误码见[API调用规范](API调用规范.md)。

## 4 资源与比赛行为

默认每步预算3秒，覆盖编码、推理、解码与重试；初次尝试后最多再重试3次，第4次失败后按策略处置。模型加载和默认预热在开局阶段完成，不计入逐步预算，但没有单独启动超时，应保持有限且可预期。

学生应保留普通Agent的`fast_local=False/is_human=False`；不要伪装成人类、设置快路径、创建后台提交线程或在回调中偷偷落子。过期的同一思考线程后续提交会被拒绝，但超时线程并不被强制终止；不要把它当作可持续工作的异步推理机制。

当前平台不限制模型大小、RAM、显存、CPU线程、启动耗时或网络访问，也没有每个学生的进程安全沙箱。因此教师需在课程比赛前另行公布并固定资源条件。建议提交者至少报告：

- 权重大小、参数量、峰值内存/显存。
- 冷启动耗时、典型与最长每步推理时长。
- 是否支持CPU；GPU型号与显存要求。
- 是否使用外部引擎、联网服务或额外数据文件。
- 随机种子、采样温度等影响复现的设置。

上述是课程交付要求；当前程序并不自动验证所有项目。正式自动比赛应选择平台驱动的Agent或`http:名字`，使用`forfeit`策略，关闭人为悔棋与重开操作。主动`api`模式目前不执行同样的比赛计时，不应默认为与自动选手公平等价。

## 6 提交前验收

从仓库根目录，在课程指定环境下执行：

```powershell
python -m pip install -r requirements-pytorch.txt
# 若学生有额外依赖，再安装其requirements.txt
python -m chessarena test agents/team_alpha.py --vs builtin:random --games 2
python -m chessarena play --white agents/team_alpha.py --black builtin:greedy --pgn runs/alpha-white.pgn
python -m chessarena play --white builtin:greedy --black agents/team_alpha.py --pgn runs/alpha-black.pgn
python -m chessarena serve --white agents/team_alpha.py --black builtin:stockfish
```

这些路径是学生提交后的示例，不是仓库已附带的TeamAlpha文件。除了普通开局，测试时应覆盖双方受将、无合法动作、易位、吃过路兵、四种升变与终局。检查是否因`error/timeout/retry_exhausted/forfeit`结束，不能只看胜负分数。

CLI的`test`会输出统计，不保证所有错误都导致非零退出码；正式验收还需看实际棋谱、终局原因与程序日志。联赛遇到`*`当前可能按半分统计，详见[平台象棋规则](平台象棋规则.md)。

## 7 权重的交付方式

现有`.gitignore`忽略`agents/weights/*.pt`与`*.pth`；仅把文件复制到该目录不会使其进入Git。新克隆默认没有A/B演示权重，需要按[使用说明](平台使用说明.md)生成。

课程可以选择随提交压缩包提供权重、通过指定下载链接及SHA256提供，或明确调整Git忽略规则并采用适合大文件的发布方式。无论使用哪种方式，助教都应在独立目录验证“获取权重→加载→执白/执黑对战”流程，不能依赖开发者电脑已有缓存。
