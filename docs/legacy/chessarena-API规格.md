# ChessArena API设计规格

当前学生接口为v2，接口清单以[API总表](chessarena-API总表.md)为准。

## 1 输入与输出

平台提供完整只读局面：棋子、走子方、王车易位权、吃过路兵目标、计数与历史。训练和正式比赛均不向学生提供候选动作、合法落点、动作掩码或平台沙盘。

学生自定义编码器、网络、规则判断和解码器。解码为UCI后调用Player.submit，或返回UCI让平台提交。所有真实落子最终经Game.submit检查；学生错误不会直接修改棋盘。

## 2 接入层

Agent提供choose_move和生命周期。TorchAgent仅管理加载、设备、eval、推理模式及开局预热，学生实现load_model、encode、decode；不同学生模型形状独立。

State为不可变数据，不保存chess.Board引用；Board只读视图也只读取State。学生self.game为绑定颜色的Player，不包含Game管理方法。训练管理脚本可以通过Arena/Game管理环境，但模型只接收State/Player。

## 3 拒绝与重试

非法/格式错误返回-1/-2，棋子、历史和轮次不变，last_error记录原因。拒绝原因不附带合法替代动作。默认初次加3次重试，共享3秒；失败的主动submit返回Result并被统一处理。

越轮、暂停或过期思考返回-3，终局返回-4。超时请求不能在后续同色回合补交。独立HTTP主动模式没有统一思考计时，需要统一评测时使用Agent/UCI/服务端主动请求的HTTP模式。

## 4 UI和通信

HTTP、WebSocket和HTTP学生服务共用数据契约。删除旧/legal_moves端点和所有快照中的legal_moves字段；浏览器chessground也不消费动作列表，提出动作后由服务端裁决并重绘。

UI用revision丢弃旧状态，支持悔棋和重开；升变选择不在前端判断完整棋规。

## 5 教学交付

学生提交入口、网络结构、权重、编码器/解码器及依赖说明，自行保证训练与比赛编码一致。平台只统一局面、动作提交和比赛生命周期，不统一张量表示。参见[模型提交规范](chessarena-模型提交规范.md)。

同进程Python插件属于可信代码，不提供账号认证或安全沙箱。平台的最终裁判职责不会因学生自行判合法而取消。
