# 平台使用说明

本文面向教师、助教和学生，按当前仓库代码说明安装、启动、观战和模型对战。接口细节见[API调用规范](API调用规范.md)，实际判定见[平台象棋规则](平台象棋规则.md)。`legacy/`是历史资料，使用时以本组五份文档及当前代码为准。

## 1 平台的作用

ChessArena提供一个本机国际象棋对战平台：chessground绘制棋盘，Python裁判维护唯一真实局面，内置五档AI，也可以加载学生自己的选手。

学生拿到只读局面，自行完成编码、网络推理、动作解码和合法性判断，再通过`submit()`向裁判提出着法。平台不提供合法动作列表、动作掩码或局面推演接口。裁判检查通过才真正落子；拒绝提交不会移动棋子。

支持三种学生接入方式：

| 方式 | 谁发起每步决策 | 适用场景 |
|---|---|---|
| `agents/*.py`中的`Agent`或`TorchAgent` | 平台调用学生代码 | 本机教学、自动比赛、A/B模型对战 |
| `api`选手与HTTP客户端 | 学生程序主动读取、提交 | 独立训练程序、其他语言接入、交互调试 |
| `http:名字`或`uci:名字` | 平台请求外部服务或引擎 | 单独启动的推理服务、UCI程序 |

**比赛计时有区别：**同进程选手和平台注册的HTTP/UCI选手接受每步预算与重试处置；主动HTTP的`api`模式当前只检查轮次和动作，不强制每步超时或累计重试判负。

## 2 安装与启动

### 2.1 环境

- Python3.10或以上；当前开发验证环境为Python3.12。
- 在仓库根目录运行命令，以便找到`config.yaml`、`agents/`和本地包。
- 前端资源已附带，不需要Node、npm或前端构建。
- 基础平台不需要PyTorch和GPU。
- 附带Stockfish19为Windows x86-64可执行文件；其他系统需自行指定兼容的Stockfish文件。

在仓库根目录打开PowerShell，推荐创建独立环境；无需修改PowerShell执行策略：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m chessarena serve
```

打开<http://127.0.0.1:8000/>。后文的`python`均指已安装依赖的同一个解释器；如未激活虚拟环境，继续使用`.\.venv\Scripts\python.exe`替代。

默认白方为人类，黑方为贪心AI。也可双击`start.bat`，它使用PATH中的`python`，在检测到部分基础依赖缺失时执行安装，并打开默认页面。若环境存在依赖不完整问题，手动运行上述完整安装命令。

### 2.2 常用启动方式

```powershell
# 人机对战
python -m chessarena serve --white human --black builtin:stockfish

# 内置AI互相对战
python -m chessarena serve --white builtin:minimax3 --black builtin:stockfish

# 两个学生模型对战，先按第4节生成权重
python -m chessarena serve --white agents/A.py --black agents/B.py

# 独立客户端执白；另开终端运行客户端
python -m chessarena serve --white api --black builtin:stockfish

# 同机双人
python -m chessarena serve --white human --black human
```

按Ctrl+C停止服务。一个服务进程只有一局当前对局；需要多个独立棋盘时，启动不同端口的服务，例如`--port 8001`。

## 3 页面操作

顶部白方、黑方下拉框选择选手。更改任一下拉框会立即按所选组合开新局；“开局”也会重开，旧局面不会自动保存为比赛记录。

| 操作 | 行为 |
|---|---|
| 点击来源格再点目标格，或拖动棋子 | 人类提交动作提案，裁判接受后生效 |
| 兵到最后一横线 | 选择后、车、象或马；裁判最终判断是否合法 |
| 翻转 | 改变观察方向，不改变坐标和模型输入方向 |
| 复制FEN、导出PGN | 保存当前局面或完整棋谱 |
| 暂停、继续 | 控制服务端自动推进；暂停时HTTP落子也会被拒绝 |
| 单步 | 让当前自动AI走一步；可在暂停状态下使用，不能替`api`选手走棋 |
| 速度 | 调整AI两步间的展示等待时间，不改变每步思考预算 |
| 悔棋 | 人机模式退回人类回合；其他组合通常退一个半步 |
| 认输 | 单个人类参赛时让该人类认输；否则让当前走子方认输 |

页面不提供合法落点提示。非法拖动后棋盘根据裁判快照重绘。SAN记谱、将军、上一步和吃子信息是显示信息，不是提交格式。

“外部AI/API”表示该方等独立程序调用HTTP接口；页面不会替该选手决策。纯观战时应选择已注册AI或模型文件。

## 4 生成并运行PyTorch示例

```powershell
python -m pip install -r requirements-pytorch.txt
python agents/examples/train_torch_demo.py --steps 20
python -m chessarena serve --white agents/A.py --black agents/B.py
```

训练脚本生成`agents/weights/A.pt`和`B.pt`。默认拒绝覆盖已有权重；如确实要重训演示模型，加`--force`，也可以使用`--out runs/new-demo`输出到其他目录。使用其他目录时，须同步修改模型入口的权重路径才能供A/B入口加载。

A/B采用不同隐藏层尺寸和独立权重。标签是随机合法动作，短训只展示接入闭环，不代表棋力。权重当前被Git忽略，克隆仓库后必须生成或从课程提供者处获得。

完整编码、训练、解码和接入过程见[PyTorch模型训练与接入示例](PyTorch模型训练与接入示例.md)；学生交付材料见[模型提交规范](模型提交规范.md)。

## 5 命令行比赛与联赛

```powershell
# 无网页比赛，保存PGN
python -m chessarena play --white agents/A.py --black agents/B.py --pgn runs/A-vs-B.pgn

# 自测并交换黑白
python -m chessarena test agents/A.py --vs builtin:greedy --games 2

# A/B循环赛，先用单进程便于排查
python -m chessarena league --players agents/A.py,agents/B.py --rounds 1 --openings 0 --concurrent 1 --out results/A-vs-B

# 终端回放PGN
python -m chessarena replay runs/A-vs-B.pgn --board --delay 0.2
```

`play`默认最多400半步；`league`默认600半步。达到上限不等于棋规和棋，结果仍可能是`*`。未完成对局单独统计，不计胜和负、不参与ELO更新；CLI的`play/test/league`存在未完成对局时返回退出码3。正式评分前应检查报告中的`unfinished`或`error`。

联赛每对选手比赛`2*rounds`局；`--openings`表示平台先随机走多少个**半步**，默认8。使用`--openings 0`从标准初始局面开始。报告包含`index.html`、`games.jsonl`、`ratings.json`和`pgn/`。

断点续跑需要继续指定**同一个**`--out`目录及相同比赛设置；默认带时间戳的输出目录每次不同。更换模型权重后应使用新输出目录，避免沿用旧结果。

联赛ELO是本次参赛组内的估计值，初始1500、K值32，不是官方等级分。非法率与步时按各自执子方统计，步时包含该回合的编码、推理、解码、重试及回调等墙钟开销，不等于纯网络前向耗时。旧记录没有单方统计字段，应重新比赛生成相应数据；详见规则文档。

## 6 配置与内置AI

内置选手：`builtin:random`、`builtin:greedy`、`builtin:minimax2`、`builtin:minimax3`、`builtin:stockfish`。L4实际采用预算约0.85秒的迭代加深；界面的档位名不代表固定搜索深度。

修改`config.yaml`后重启服务。例如：

```yaml
server:
  host: 127.0.0.1
  port: 8000
game:
  timeout: 3.0
  max_retries: 3
  on_retry_exhausted: forfeit
  on_timeout: forfeit
stockfish:
  elo: 2600
  movetime: 1.0
  path: thirdparty/stockfish-windows-x86-64-universal.exe
```

`max_retries: 3`允许首次尝试后再重试3次，即第4次被拒后处置。全部尝试共享一个`timeout`预算。正式自动比赛应使用`forfeit`；`random`会由平台随机替走，适合调试，影响模型比赛结果。

`serve/play`命令中的显式时限、重试参数覆盖配置。`league`的轮数、开局、并发、步时等使用其CLI参数默认值，应显式传参，不能假定会读取同名YAML字段。

Stockfish的强度和思考时长可通过`CHESSARENA_STOCKFISH_ELO`、`CHESSARENA_STOCKFISH_MOVETIME`覆盖；建议引擎思考时间小于平台预算。路径查找依次尝试传入路径、`CHESSARENA_STOCKFISH`、默认路径；若要使用其他系统的引擎，可直接修改YAML的`path`。引擎来源和源码见[第三方分发说明](../thirdparty/README.md)。

## 7 排查问题

| 现象 | 检查方式 |
|---|---|
| `No module named chessarena` | 回到仓库根目录，确认使用正确解释器 |
| 端口被占用 | 使用`--port 8001`并访问相应地址 |
| 模型在下拉框但不能开局 | 扫描不会加载权重；检查PyTorch安装、权重路径与结构是否匹配 |
| AI不动 | 查看是否暂停、是否轮到`api`选手，访问`/debug`并查看终端错误 |
| 一直非法或重试判负 | 核对矩阵方向、执子颜色、易位/升变编码，检查学生解码器 |
| Stockfish打不开 | 核对平台和exe架构、文件路径；Windows附带exe不适用于Linux/macOS |
| CLI比赛未结束 | 查看`--max-plies`，提高上限或检查策略是否循环 |

本平台面向受信任的本机教学程序。`side`用于轮次检查，不是账号认证；控制接口可重开、悔棋。Python同进程选手也不是进程隔离沙箱。若需要严格公平的正式评分，应使用受控的比赛运行方式，并按[平台象棋规则](平台象棋规则.md)确认当前限制。
